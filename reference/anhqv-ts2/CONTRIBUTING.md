# Contributing to the ANHQV × The Sims 2 Preservation Project

Thank you for helping preserve and investigate the world of *Aquí no hay quien viva* through *The Sims 2*.

The project welcomes contributions from simmers, ANHQV specialists, researchers, editors, archivists, programmers, artists, translators, and curious people who are willing to work carefully with evidence.

## Ways to Participate

Use the GitHub issue forms for:

- a research question;
- an evidence correction;
- an experiment proposal;
- a source suggestion;
- interest in a formal contributor role.

A pull request is appropriate when the proposed change is already concrete and reviewable.

Examples include:

- correcting a documented error with evidence;
- improving a source record;
- clarifying a method;
- adding an experiment result;
- improving navigation or formatting;
- contributing a rights-cleared diagram, transcript, or edit log.

## Formal Roles and Public Proposals

Anyone may propose an improvement.

Formal mission roles and repository permissions are assigned through recruitment and onboarding. An accepted issue or pull request does not automatically grant a formal role, and a person does not need a formal role before offering a useful correction.

This distinction lets the project remain open without abandoning review.

## Evidence Requirements

State clearly whether a claim is:

- observed;
- inferred;
- hypothesised;
- speculative;
- concluded from identified evidence.

For ANHQV claims, include the most precise source available, such as:

- episode and timestamp;
- dialogue and speaker;
- DVD edition and chapter;
- interview, article, or source-record ID;
- a clearly labelled recollection that still requires verification.

For Sims 2 claims, include relevant conditions, such as:

- game edition and patch state;
- operating system or compatibility layer;
- installed mods or custom content;
- lot, neighbourhood, and build configuration;
- exact procedure;
- screenshots, logs, package evidence, or experiment run ID.

A negative or inconclusive result is still useful when the method is documented.

## Sources and Copyright

Do not upload material merely because it is publicly accessible.

Before submitting third-party material, identify:

- the creator or rights holder;
- the source and access date;
- the licence or permission basis;
- any embedded material not covered by that permission;
- whether quotation or linking would serve the research purpose better than copying.

Substantial episode footage, television audio, commercial music, game files, press scans, and full website mirrors will not be accepted without a documented legal and preservation basis.

## Raw Media

Do not submit raw experiment recordings directly to GitHub.

Raw evidence should remain unchanged in the designated evidence archive. Public edits must be new exports and include an edit log describing:

- source recordings;
- cuts and timing changes;
- audio processing;
- captions and annotations;
- obscured private or irrelevant material;
- any edit that might change how evidence is interpreted.

## Pull Request Workflow

1. Open or link an issue where practical.
2. Keep one pull request focused on one subject.
3. Explain what changed and why.
4. Identify evidence and uncertainty.
5. Confirm rights and privacy status.
6. Update indexes, histories, and cross-links when needed.
7. Respond to moderator review.

Canonical documentation is merged by moderators after review.

## Style

- Use British English unless quoting a source.
- Use *Aquí no hay quien viva* and *The Sims 2* as formal titles.
- Use ISO dates (`YYYY-MM-DD`) in metadata and filenames.
- Use stable experiment and source identifiers.
- Prefer clear prose over institutional jargon.
- Preserve humour where it helps the project remain human, but never let a joke obscure evidence status.

See [Naming](00%20Project/Naming.md) for canonical forms.

## Review and Correction

Moderators review process, not truth by decree.

A reviewer may ask for:

- stronger evidence;
- clearer uncertainty;
- a smaller claim;
- rights clarification;
- a reproducible procedure;
- an experiment rather than argument.

Changing a conclusion in response to evidence is a successful contribution.

## Contributor Attribution

Use your preferred public name or stable identifier. Contributors are not required to publish a legal name.

Significant contributions should be reflected in document history, Git history, acknowledgements, or contributor archives as appropriate.
